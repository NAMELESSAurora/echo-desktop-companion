# 管线结构与阶段边界

本阶段按 2026-10-25 的新范围执行：先做后端管线，预留 DeepSeek Flash 的三个角色和 Qwen AUDIO 3.1 TTS。原计划中的前端宿主选型、ASR 和形象定制顺延。

```text
HTTP 请求
  → 会话锁定与 request_id 去重
  → 截图权限与来源版本检查（有图片时）
  → 已确认事实 + 有界文字历史
  → DeepSeek dialogue / vision 流
       ├→ text.delta → SSE 客户端
       └→ 分句 → 队列 4 项 → Qwen TTS SSE → PCM audio.chunk
  → 完整文字轮次原子落盘 → 唯一终态事件

已完成的文字用户消息
  → 显式启动整理任务 → 独立后台槽位 → DeepSeek memory JSON
  → 校验消息来源与记忆 epoch → proposals
  → 明确确认 → 同角色事实
```

## 模块

- config.py：环境变量、默认模拟模式、模型和端点配置。
- models.py：输入约束、图片边界、记忆结果结构。
- providers.py：供应商协议与模拟服务；HTTP 连接可取消；不输出 reasoning_content。
- pipeline.py：前台调度、分句队列、打断、降级、后台任务与终态一致性。
- events.py：有界事件回放、游标与中文分句。
- store.py：SQLite 事务、会话、文字历史、事实、任务、epoch。
- api.py / middleware.py：Bearer 鉴权、Origin／Host 限定、体积限制和 HTTP/SSE。

## 已实现与未验证

已经实现并以离线协议测试验证请求映射、事件顺序、取消、音频排队、记忆状态与恢复。真实供应商仅有适配器，没有进行带真实 Key 的调用，因此账号区域、音色许可、延迟、音质、账单和服务稳定性仍待验证。

所有依赖被 uv.lock 固定。测试没有启动现有用户项目，也没有修改宿主软件。本项目的 `.local` 为独立的试验数据根。

## 后续接入时需保持的约束

1. 选定宿主的前端只需发送文本／指定窗口帧、消费事件和发出取消。ASR 后续输出文本即可复用当前入口。
2. 宿主与本服务二选一承担正式记忆存储。不能同时开启两套自动学习后再双向同步。
3. 声音播放与角色口型由客户端负责。前端已用实际 PCM 输出信号驱动形象开合；后端没有音素时间标记，不能声明音素级嘴形或真实模型延迟已验收。
4. 客户端取消本地播放与服务端取消调用都需要执行；已进入网卡或设备缓冲的旧音频必须在客户端丢弃。
5. 候选事实确认流程、历史失效策略和采样频率先通过日常体验验证，再考虑自动化，不能把测试音频当成产品体验。
